# 向量索引实现更换（2026-11-17）

## 1. 问题：知识库建不了库

现象：教师点「重新建库」报错，知识库页四类资料都显示「0 个索引片段」。

```
{"status":"error","message":"DLL load failed while importing hnswlib: 应用程序控制策略已阻止此文件。"}
```

这是两个独立问题叠加，都不是代码改动引起的：

**（1）旧索引与新代码不匹配**

2026-11-03 的 RAG 重写（`0ab423d`）把索引改成「按代构建 + `active-index.json` 原子切换」，
collection 名从固定的 `lecture / solutions / buglib / kp_points` 改成 `rag_<gen>_<category>`。
而 `data/vector_db/` 里只有 10-29 生成的旧 Chroma 目录（`chroma.sqlite3` + 四个 UUID 文件夹），
没有 manifest，新代码读不到活动索引：

```python
def stats():
    manifest = rag_index.read_manifest(config.VECTOR_DB_DIR)
    return dict(manifest['counts']) if manifest else {c: 0 for c in COLLECTIONS}
```

所以界面显示 0；检索时 `_vector_candidates()` 拿不到 manifest 直接返回空，自动走词法检索，
**演示时对话与诊断照常可用，只是没有向量召回**。

**（2）重建被系统策略拦截**

建库需要 chromadb 写 HNSW 集合，chromadb 依赖 `hnswlib.cp312-win_amd64.pyd`。
该原生库未签名，被 Windows 智能应用控制（Smart App Control，代码完整性策略
`{0283ac0f-…} VerifiedAndReputableDesktop`）拒绝加载。

证据（`Microsoft-Windows-CodeIntegrity/Operational`）：

| 时间 | 被拦截的文件 | 说明 |
|---|---|---|
| 2026-10-29 19:54–21:16 | `torch_python.dll` × 24 | 后来换 ONNX 解决；当天 21:20 chromadb 建库成功，说明 hnswlib 当时可加载 |
| 2026-11-08 18:37 | — | 策略 `VerifiedAndReputableDesktop` 刷新并激活 |
| 2026-11-16 起 | `hnswlib.cp312-win_amd64.pyd` | 事件 3077/3033：`did not meet the Enterprise signing level requirements` |

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState = 1`（强制启用）。
智能应用控制只能重装系统才能关闭，不适合为一个课程项目改动整机安全设置。

## 2. 方案：numpy 暴力余弦检索

课程语料只有几百个分块（当前 334 个），暴力检索是微秒级，没有必要为此引入近似最近邻索引和原生扩展。

- `rag_index.py`：一代索引 = 一个目录
  - `gen-<generation>/vectors.npy`：float32 矩阵，行已 L2 归一化
  - `gen-<generation>/chunks.json`：与矩阵行序一一对应的片段元数据（含 `chunk_id`、`content_hash`、分类等）
  - `active-index.json`：原子切换的清单（`format: 2`，新增 `dir` 与 `dim`）
- `rag.py`：`_vector_candidates()` 用 `matrix @ query` 得到余弦相似度，`1 - 相似度` 作为距离，
  仍按 `RAG_MAX_DISTANCE` 过滤，再与词法结果做 RRF 融合。
- 不再 import chromadb；`requirements.txt` 去掉 `chromadb`，`rag.py` 删掉 `np.float_` 兼容垫片。
- 保留原有语义：同版本+同模型签名直接返回缓存计数；同一模型下按 `content_hash` 复用旧代向量；
  构建失败不修改活动 manifest；只保留当前代与上一代（上一代用于复用）。

## 3. 升级步骤

已有部署升级后由教师点一次「重新建库」即可（约 10 秒，首次会加载 ONNX 模型）。
旧的 `data/vector_db/chroma.sqlite3` 与四个 UUID 目录不再被读取，可以手动删除，不影响功能。

## 5. 边界

- 分块数在千级以内暴力检索足够（334 × 512 维矩阵约 0.7MB，点积 <1ms）。
- 语料增长到数万分块时再考虑 ANN（faiss / hnswlib）或 BM25 为主、向量只做精排；
  届时换实现只需改 `rag_index.load_generation()` 与 `rag._vector_candidates()`，manifest 与上层不变。
