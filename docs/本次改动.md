## 2. 数据库：合并与迁移

**新增** `backend/app/core/db.py`：唯一连接入口 + 建表 + 旧库迁移。

- 数据库：`backend/data/app.db`，WAL 模式，`foreign_keys=ON`
- 表：`users / conversations / messages / code_analyses / classes / class_members / assignments / submissions / meta`
- `app/core/store.py` 全部改为使用 `db.get_conn()`，新增班级、任务、提交、看板相关函数
- `app/core/database.py` 变成兼容层（`get_db` 仍可用），不再自己建表

**迁移逻辑**（`init_db()` 启动时执行，幂等）：

1. 给旧表补列：`users.role`、`users.display_name`、`conversations.updated_at`、`code_analyses.diagnosis`
2. `ATTACH` 旧 `chat.db`，按 id `INSERT OR IGNORE` 复制 `conversations / messages / code_analyses`
3. 迁移时临时关闭外键检查（旧库可能有不一致数据），完成后 `DETACH`
4. 在 `meta` 表写 `legacy_chat_migrated=1`，不会重复迁移；`chat.db` 原样保留，可回退

> 本次实际迁移结果：conversations 2 条、messages 2 条。

## 3. 安全

### 3.1 SECRET_KEY

`app/core/auth.py` 不再硬编码。优先级：

1. 环境变量 `SECRET_KEY`
2. `backend/data/.secret_key`（首次启动自动生成并写入）
3. 都没有时生成随机值

改完后旧 token 全部失效，所有人需重新登录（一次性影响）。

### 3.2 BYOK（自带密钥）

- 前端 `src/session.js`：key 存 `sessionStorage`，勾选"记住本机"才写 `localStorage`
- 前端 `src/api.js`：每个请求带 `X-LLM-Key` 头
- 后端 `app/core/llm.py`：`chat_stream(api_key=...)`，自带 key 时**每次新建客户端**，不缓存别人的密钥
- 后端只在内存里使用，不写库、不写日志；`/api/llm/status` 只返回"有没有服务端 key"的布尔值
- 服务端 `.env` 的 key 变成兜底：没填个人 key 的用户会回退（演示方便），不填也能启动

### 3.3 权限

| 接口 | 学生 | 教师 |
|---|---|---|
| 建班级 / 发任务 / 看板 / 看某任务全部提交 | 403 | 仅自己创建的班级 |
| 加入班级 | ✅ | 不能加入自己的班 |
| 看班级成员、任务 | 仅本班 | 本班 |
| 提交代码/文字 | 仅本班 | 不能提交 |
| 重建知识库 `/api/knowledge/ingest` | 403 | ✅ |
| 单个提交详情 | 仅自己 | 本班 |
| 看别人会话 / 别人的剖析记录 | 403 | 403 |

`get_current_user` 现在每次请求都回库查 `role`，不只信 token 里的字段。

## 5. AI：结构化诊断 + 知识点检索

### 5.1 诊断协议（`app/agents/prompts.py`）

在代码诊断的 system prompt 末尾追加：回复最后必须输出

```
<<<DIAG
{"error_types": ["指针顺序错误"], "kp_ids": ["ds-01-02"], "severity": "high", "hint_level_reached": 2, "next_question": "..."}
DIAG>>>
```

- `error_types` 限定在 10 个词表里（断链/悬空指针/内存泄漏/越界/空指针/递归基线缺失/树旋转失衡/循环边界/指针顺序错误/其他）
- `kp_ids` 只允许本次检索到的知识点 id
- `hint_level_reached` 记录实际给到第几阶提示（评估"有没有在引导"）

### 5.2 流式剥离（`app/agents/stream_filter.py`）

边收边过滤：哨兵之前照常流式给前端，哨兵之后攒起来；末尾扣住半个哨兵（`<<<DI`）不漏给学生。

### 5.3 解析与兜底（`app/agents/diagnosis.py`）

- 容忍 ```json 围栏、前后多余文字
- 字段校验：错因必须在词表内、kp_id 必须符合 `ds-xx-xx`、severity 三选一、hint 1-3
- 模型没按格式输出时，用静态线索兜底（`source: "heuristic"`），保证看板不空

### 5.4 知识点库（kp）

- `data/knowledge/kp/*.md`，front matter 见 `kp/README.md`
- `app/utils/kp_meta.py`：零依赖解析 front matter，`to_vector_metadata()` 直接给 Chroma 用
- `app/core/rag.py`：新增 collection `kp_points`（chromadb 要求名字长度 ≥3，所以不能叫 `kp`），按 `##` 小节分块，metadata 带 `kp_id / chapter / difficulty / prereq / tags`
- 检索返回统一带 `kp_id / title / chapter / difficulty / section`
- **关键词降级**：向量模型不可用时自动改用二字组匹配（`_lexical_search`），保证"检索带 kp_id"在任何机器上都能跑

## 12. 严格 BYOK（同日，安全问题修复）

### 12.1 现象

使用者没有在页面里填 key，对话照样能回答。原因是 `core/llm.py` 里写了一句兜底：

```python
key = (api_key or "").strip() or DEEPSEEK_API_KEY   # ← 没传个人 key 就用服务端的
```

服务端 key 来自 `backend/.env`，实测确认：

- `.env` **从未提交过**（`git log --all -- backend/.env` 为 0 条）
- `.env` 在 `.gitignore` 里
- 全仓库被跟踪的文件里只有占位符（`.env.example`、`TELLME.md`、`SettingsModal.vue` 的 `placeholder="sk-..."`），没有真实密钥
- 所以 key 没有写进代码，只是被"兜底逻辑"用了

### 12.2 改动

| 文件 | 改动 |
|---|---|
| `app/config.py` | 新增 `ALLOW_SERVER_KEY`，默认 `0` |
| `app/core/llm.py` | 只有 `ALLOW_SERVER_KEY=1` 时才回退到服务端 key；否则报"请在模型设置里填写你自己的 Key" |
| `app/api/llm.py` | `/api/llm/status` 增加 `server_key_configured`、`allow_server_key`；`server_key` 表示"当前是否可用" |
| `.env.example` | 明确默认不启用服务端 key |
| `README.md` / 本文档 | 同步说明 |

### 12.3 验证

- 不带 `X-LLM-Key` 请求 `/api/chat`：返回 `{"error": "未配置模型密钥：请在页面右上角「模型设置」里填写你自己的 API Key"}`，不发起任何模型调用
- 带 `X-LLM-Key`（用 `.env` 里的 key 模拟"个人 key"）：正常流式返回
- 状态接口：`server_key=false`、`server_key_configured=true`、`allow_server_key=false`

### 12.4 本机演示怎么办

自己的机器上想省事，可以在 `backend/.env` 里加一行 `ALLOW_SERVER_KEY=1` 并用服务端 key 兜底；
**部署给别人用的环境不要开**，否则别人不填 key 也会花你的额度。

### 12.5 作业提交的保存策略（当前设计）

- `submissions` 表对 `(assignment_id, user_id)` 做了唯一约束，**重交会覆盖上一次**；
  教师看板和作业中心看到的都是"最近一次提交"
- 代码类每次提交都会另存一条 `code_analyses`（AI 分析全文），所以代码的历次 AI 诊断仍能在
  「学习助手 → 代码诊断」的左侧历史里找到；问答类没有历史，覆盖后旧答案不可恢复
- 如果以后需要"第几次提交 / 每次都留档"，加一张 `submission_attempts` 表即可，
  现有 `submissions` 可以保留为"最新一次"的视图
