# 查找

## 顺序查找

逐个比较，O(n)。无需有序，适用于链表等不支持随机访问的结构。

## 二分查找

要求有序顺序表。每次与中间元素比较，缩小一半区间，O(log n)。关键是维护 `low`/`high` 区间，终止条件 `low > high`。求中点用 `mid = low + (high - low) / 2` 避免整数溢出。

## 哈希查找

通过哈希函数把 key 映射到桶。冲突处理分**开放定址法**（线性探测、二次探测）与**链地址法**（拉链）。查找/插入/删除平均 O(1)，最坏 O(n)。

## 易错点与考点

- 二分查找的**循环边界**：`while (low <= high)` 还是 `<`，配合 `mid` 的更新方向，写错会漏判端点或死循环。
- 二分查找返回「插入位置」而非「是否存在」的变体（lower_bound）是高频考点。
- 哈希的**删除**：开放定址法删除不能物理置空，否则会切断探测链，需用「墓碑」标记。
- 装填因子过高会导致探测链变长、性能下降，需扩容重哈希。
- 好的哈希函数应使 key 均匀分布，减少冲突。
