## 概念

栈是**只允许在一端插入和删除**的线性表，这一端叫栈顶（top），另一端叫栈底。它的行为是后进先出（LIFO）：最后放进去的元素最先被取出。这个限制看起来是在削弱能力，实际是把问题变简单——凡是"最近一件还没处理完的事优先"的场景，栈都是天然选择：函数调用的返回地址、编辑器的撤销、括号配对、深度优先搜索的回溯，本质上都在做同一件事。

顺序栈用一段连续数组加一个栈顶下标实现，容量固定，但访问快、没有指针开销；链栈用单链表实现，把**栈顶放在表头**，入栈就是头插、出栈就是删除首元结点，两者都是 O(1)，也不会溢出（只受内存限制）。同一个功能有两套实现，选哪个取决于"元素个数是否可以预估"和"愿不愿意为每个元素多付一个指针"。

两种实现都必须回答同一个问题：**空栈和栈顶下标怎么约定**。常见两种约定：`top` 指向栈顶元素（初值 -1，入栈先 `++top` 再写入），或 `top` 指向"下一个空位"（初值 0，入栈先写入再 `++top`）。两种都对，但同一个文件里只能有一种，混用就会出现"少存一个元素"或者"多写一格踩内存"。

## 要点

- 栈的核心约束是"只在一端进出"，因此 push/pop 都是 O(1)，代价是不能随机访问中间元素。
- 顺序栈（top 指向栈顶元素）：空栈 `top == -1`，栈满 `top == MAXSIZE - 1`，入栈 `s[++top] = x`，出栈 `return s[top--]`。
- 链栈把栈顶放在表头：push 是头插，pop 是删除首元结点；若把栈顶放表尾，push 就得先遍历整条链。
- 顺序栈会溢出、链栈不会（只受内存限制）；但链栈每个元素多一个指针，结点分散、缓存不友好。
- 栈空时 pop 必须先判空：在顺序栈里不判空往往不崩溃，读到的是旧数据，这比直接崩溃更难查。

## 典型错误

### 错误 1：top 的两种约定混用

- 现象：栈最多只能存 `MAXSIZE - 1` 个元素；或者存满时程序崩溃、退出后别的变量被改坏；打印出来的元素个数总比实际少一个。
- 原因：初始化按"top 指向栈顶元素"写成 -1，判满却按"top 指向下一个空位"写成 `top == MAXSIZE`；两套约定的初值、判空、判满、写入时机全都差一位，拼在一起必然有一处对不上。
- 引导问题：你的 `top` 现在指向"已经存进去的最后一个元素"还是"下一个可以写入的空位"？你说的空栈判断对应的是哪一句？

### 错误 2：出栈写成 s[--top]

- 现象：每次出栈拿到的都是栈顶下面那个元素，或者第一次出栈就取到一个没初始化过的垃圾值；连续出栈时结果整体错位一格。
- 原因：取值方式必须与 `top` 的含义一致。top 指向栈顶元素时，应先取 `s[top]` 再 `--top`；写成 `s[--top]` 等于先退一格再取，取的是栈顶元素的下一个位置。
- 引导问题：出栈这一行里，你是先读值还是先移动 `top`？读值那一刻，`top` 指的格子里装的是谁？

### 错误 3：链栈把栈顶设在表尾

- 现象：功能正确但很慢，n 次入栈是 O(n²)；数据量大时明显卡顿，和"栈操作都是 O(1)"的印象对不上。
- 原因：单链表只能单向走，表尾结点没有前驱信息，插入新表尾必须从表头一路找过去；出栈时为了更新表尾指针也得再走一趟。
- 引导问题：单链表哪一端的插入删除是 O(1)？栈只在"一端"操作，你为什么没有把那一端设成栈顶？

### 错误 4：栈空时直接 pop

- 现象：顺序栈上通常不崩溃，但取回一个很久以前被覆盖的旧值，上层逻辑莫名其妙地算错；换成链栈就变成崩溃。
- 原因：没有判空，`top` 已经到 -1 还继续 `s[top--]`，读的是数组范围外的位置；链栈则是把 NULL 当作结点解引用。
- 引导问题：调用 pop 之前，谁能保证栈里一定还有元素？这个保证应该写在 pop 里面还是调用方？

## 分级练习

### 练习 1：补全顺序栈的四个基本操作（难度：1）

- 题面：给定结构体（数组 `data` 加 `top`，采用"top 指向栈顶元素"的约定），补全 `isEmpty`、`isFull`、`push`、`pop`，要求在栈满、栈空时返回失败标志而不是崩溃。
- 一阶提示（反问）：空栈和栈满时，`top` 的值分别是什么？这两个值会不会出现一样的情况？
- 二阶提示（定位到行）：判满应该放在"移动 top"之前还是之后？`push` 里是先 `++top` 再写，还是先写再 `++top`？
- 三阶提示（伪代码/类比）：像往只有固定格子的药柜里放药瓶，先看最上面那格是不是已经到顶了，再决定能不能往上加一格。
- 验收点：连续 push 到满之后再次 push 返回失败且不越界；空栈 pop 返回失败；出入栈顺序是标准的后进先出。

### 练习 2：判断出栈序列是否合法（难度：3）

- 题面：入栈序列固定为 1, 2, …, n，每一步可以入栈也可以出栈，判断给定的出栈序列能否由某个合法操作序列得到，并说明为非法时卡在哪一步。
- 一阶提示（反问）：要输出序列里的第一个数，栈里必须先压入哪些数？这些数之后还能以什么相对顺序出来？
- 二阶提示（定位到行）：用一个指针 j 扫描入栈序列、一个栈做模拟；什么时候只能入栈，什么时候可以出栈？如果栈顶不是当前想要的数，你还有别的选择吗？
- 三阶提示（伪代码/类比）：像只有一条铁轨的调车场，车厢只能从一头进、同一头出，先进去的被堵在里面，想让它先出来得先把上面压着的挪走。
- 验收点：3,1,2 判为非法、1,2,3 与 3,2,1 判为合法；n=1 和 n=5 的用例都正确；不修改输入序列，栈用完清空。

### 练习 3：改成链栈并解释复杂度（难度：2）

- 题面：把练习 1 的顺序栈换成带头结点的链栈，保持同样的四个接口，并写一段话说明为什么栈顶必须放在表头。
- 一阶提示（反问）：push 和 pop 都发生在栈顶，你希望这个位置离链表表头多远？
- 二阶提示（定位到行）：如果采用头插法，`push` 里还需要循环吗？如果把栈顶放到表尾，`pop` 之后新的表尾你打算怎么找？
- 三阶提示（伪代码/类比）：像一摞盘子，最上面那个永远最好拿；非要把新盘子摞在队尾，就得每次从队头走过去一趟。
- 验收点：push/pop 均为 O(1) 且不含循环；连续 1000 次 push 再 1000 次 pop 的顺序与值都正确；链栈析构后无泄漏。
