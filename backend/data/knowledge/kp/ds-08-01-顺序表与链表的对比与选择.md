## 概念

顺序表和链表是线性表的两种物理实现，差别只在「元素在内存里怎么放」。顺序表用一段连续空间加一个长度变量 `length`，第 i 个元素就存在 `a[i]` 里，所以按下标访问是 O(1)；代价是插入和删除必须搬移元素——在下标 i 处插入，要把 i 及其后的元素整体后移一位，平均搬 n/2 个，是 O(n)。链表用一个个独立结点加指针串起来，元素在内存里可以东一块西一块，所以按下标找第 i 个元素必须从头数，O(n)；但只要手里已经握着前驱结点，插入和删除只改两根指针，O(1)。

于是「谁更好」没有绝对答案，只有「对哪种操作更好」。选型要看三件事：一是操作比例，查多改少用顺序表，在已知位置频繁插删用链表；二是长度是否可预估、变化是否剧烈，长度稳定用顺序表，忽大忽小用链表，因为顺序表要么预留容量浪费空间，要么扩容时重新分配并整体拷贝；三是常数与硬件，顺序表内存连续，遍历时能把整块数据读进缓存，实际跑起来常常比链表快好几倍，而链表每跳一个结点都可能是一次缓存缺失。再加上顺序表不用为每个元素额外存指针、链表则为指针域多付一份空间，这两笔开销也要一起算进来。

## 要点

- 顺序表按下标访问 O(1)，按位置插入/删除平均 O(n)（要搬元素）；链表查第 i 个 O(n)，已知前驱时插删 O(1)。
- 顺序表内存连续、能利用缓存，遍历的常数因子小；链表结点分散，指针跳转容易缓存不命中。
- 顺序表要么预留容量（可能浪费），要么扩容时重新分配并拷贝；链表每个结点多一个指针域的开销。
- 选型判据是操作比例：查多改少选顺序表，在已知位置频繁插删选链表。
- 「链表插入是 O(1)」省略了前提——必须是「已经站在插入位置上」，按位置 i 插仍是 O(n)。

## 典型错误

### 错误 1：说「链表插入删除是 O(1)」，忽略找位置的代价

- 现象：题目要求「在第 i 个位置插入元素」，学生在复杂度一栏填 O(1)，可代码里明明先写了一个从头走 i 步的循环，两处结论自相矛盾。
- 原因：只记住了「插删只改两根指针」，漏掉前提。对「已知结点指针」的插删才是 O(1)；对「按位置 i」的插删，先要 O(n) 地定位，总代价仍是 O(n)。
- 引导问题：要改写 p 的 next，你得先拿到 p 这个指针，它是题目白送的，还是要你自己从头走 i 步才找得到？

### 错误 2：把顺序表「按下标访问 O(1)」当成「查找 O(1)」

- 现象：题目问「在顺序表中查找值为 x 的元素」，学生答 O(1)；但旁边写的代码是一个 for 循环逐个比较，答案和代码互相打脸。
- 原因：把「`a[i]` 是 O(1)」推广成了「找任何东西都是 O(1)」。无序表的按值查找必须逐个比较，是 O(n)；只有在有序表上做二分才是 O(log n)，而那靠的是「有序」这个额外条件。
- 引导问题：题目给你的 x 是下标还是值？如果你只知道值，怎么知道它在下标几？不知道下标，`a[i]` 里的 i 从哪来？

### 错误 3：遍历链表时每一轮都从头走，把 O(n) 写成 O(n²)

- 现象：程序结果完全正确，但 n 到十万级就超时；把同样的数据换成顺序表就过了，学生以为「链表天生慢」，于是放弃优化。
- 原因：循环体里反复取「第 i 个元素」，而取第 i 个元素本身又是一个从头遍历的循环，两层嵌套，总步数是 1+2+…+n，量级 n²。这不是链表的错，是用法把链表的优势抵消掉了。
- 引导问题：你那个「取第 i 个结点」的循环，单次最多走多少步？外层循环又跑多少次？两者乘起来是几阶？

## 分级练习

### 练习 1：为三个场景各选一种结构并说明理由（难度：1）

- 题面：分别给出选择与理由——(A) 学生成绩单，主要操作是按学号（即下标）查分，几乎不增删；(B) 一份通讯录，程序始终持有当前结点的指针，经常在它后面插入、删除；(C) 一段日志缓冲，长度变化剧烈，且经常在中间位置插删。
- 一阶提示（反问）：这三个场景里，「查」和「改」哪个出现得更频繁？你数得出来吗？
- 二阶提示（定位到行）：A 的关键操作是 `a[i]` 还是「找某个值」？B 里那个「当前结点指针」是题目已经给你的，还是你还要自己找？C 里长度剧烈变化，顺序表扩容那一行会发生什么？
- 三阶提示（伪代码/类比）：顺序表像一排固定座位，报座位号立刻坐下，但中间要加人就得全体往旁边挪；链表像手拉手的一队人，插一个人只需两边松手重牵，但想找第 20 个人只能从头数。
- 验收点：A 选顺序表（O(1) 随机访问、无插删搬移）；B 选链表（已知前驱时插删 O(1)，不需要搬移）；C 选链表（避免扩容拷贝与中间插入的大规模搬移）；三条理由分别对应「访问」「插删」「扩容」而不是空泛地说「链表快」。

### 练习 2：顺序表在下标 i 处插入元素，搬移方向怎么定（难度：2）

- 题面：顺序表 `a[0..n-1]`，当前长度 n，容量足够，要在下标 i 处插入 x（0 ≤ i ≤ n），其余元素相对顺序不变。有同学写成了下面这样，请指出问题并说明正确的搬移方向与顺序。

  ```text
  for (j = i; j < n; j++)
      a[j + 1] = a[j];   /* 从前往后搬 */
  ```

- 一阶提示（反问）：第一轮就把 `a[i]` 写进了 `a[i+1]`，那 `a[i+1]` 原来存的那个元素去哪了？后面还读得到它吗？
- 二阶提示（定位到行）：看循环的起点和方向——j 从小到大递增时，被写入的 `a[j+1]` 是不是「还没被搬走的元素」所在的位置？把 j 改成从 n-1 递减到 i 再想一遍。
- 三阶提示（伪代码/类比）：像一排坐满人的电影院临时加座，必须让最右边的人先挪，一个个往右让，否则右边的人还没起身就被占了位子。
- 验收点：能从 n-1 递减到 i 执行 `a[j+1] = a[j]`，再写 `a[i] = x`、长度加一；i = n 时相当于追加、i = 0 时整体后移一位；插入后序列恰为原序列在 i 处插入 x，且没有元素被覆盖丢失。

### 练习 3：解释同一段代码在两种结构上的巨大耗时差（难度：3）

- 题面：某程序按下标依次访问全部元素，写成「循环 i 从 0 到 n-1，每轮调用 get(i)」。同样的写法，n = 200000 时链表版本超时、顺序表版本瞬间跑完。请从复杂度与硬件两个层面解释差距，并把链表版本改到 O(n)。
- 一阶提示（反问）：链表 `get(i)` 单次要走多少步？把 i 从 0 数到 n-1 全部加起来是多少步？顺序表的 `a[i]` 又是几步？
- 二阶提示（定位到行）：问题出在每轮循环开头那句「从 head 重新开始」——能不能让指针在上一次停下的位置继续往前走，而不是回头？循环里真正需要的到底是「下标 i」还是「下一个结点」？
- 三阶提示（伪代码/类比）：链表正确的用法是「手里牵着一根线边走边用」，每轮 `p = p->next` 顺下去；而不是每轮都跑回队首，从头数到第 i 个人。
- 验收点：能算出链表版本总步数 1+2+…+n 即 O(n²)、顺序表 O(n)；能提到顺序表连续内存带来的缓存命中优势（常数更小）；改法是让一个指针随循环推进，复杂度降为 O(n)，且不再需要「取第 i 个」这个操作。
