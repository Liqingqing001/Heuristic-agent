## 概念

堆是「用数组存下来的完全二叉树」：不存任何指针，父子关系靠下标算——从 0 开始编号时，下标 i 的孩子是 `2i+1` 和 `2i+2`，父亲是 `(i-1)/2`（向下取整）。大根堆的性质只有一句：**每个结点都不小于它的孩子**，所以最大值一定在堆顶 `a[0]`。注意这个约束只作用在父子之间，兄弟之间没有大小关系——堆不是二叉排序树，对它做中序遍历不会得到有序序列，这是学生最容易混的一点。

堆排序分两步。第一步建堆：从最后一个非叶结点（下标 `n/2 - 1`）往前走，对每个结点做一次「下滤」（sink）。直觉上建堆是 O(n log n)，其实总代价是 O(n)：因为绝大多数结点都在最底层，它们的下滤距离很短，把所有结点的下滤距离加起来是收敛的。第二步反复取最大值：把堆顶和当前末尾交换，堆的有效长度减一，再对新堆顶做一次下滤恢复堆性质，重复 n-1 次，数组就变成升序。整个过程原地进行，时间 O(n log n)，不稳定。

下滤是唯一需要背的骨架：只要 i 还有左孩子，就取出两个孩子里较大的那个，父不小于它就停，否则交换并继续往下走。

```text
sink(a, i, n):                       // 0 起下标，堆的有效大小为 n
    while 2*i + 1 < n:               // 还有左孩子
        child = 2*i + 1
        if child + 1 < n and a[child+1] > a[child]:
            child++                  // 两个孩子取较大的
        if a[i] >= a[child]: break   // 父已不小于孩子，堆性质满足
        swap(a[i], a[child])
        i = child                    // 继续往下沉
```

建堆与排序只差两行：

```text
build_heap(a, n):
    for i = n/2 - 1 down to 0:       // 最后一个非叶结点往前
        sink(a, i, n)
heap_sort(a, n):
    build_heap(a, n)
    for end = n - 1 down to 1:
        swap(a[0], a[end])           // 堆顶最大值落到它的最终位置
        sink(a, 0, end)              // 有效堆长度缩小为 end
```

## 要点

- 下标关系（0 起）：孩子 `2i+1`、`2i+2`，父亲 `(i-1)/2`；若改用 1 起编号则是 `2i`、`2i+1`、`i/2`——写代码前先明确用哪一种，混着写必错。
- 建堆必须从 `n/2 - 1` 往前（递减）遍历：下滤的前提是 i 的两个子树已经是堆，只有从底层往上才满足这个前提。
- 下滤循环的条件是 `2*i + 1 < n`（左孩子存在），`<=` 差一就读到堆外。
- 排序阶段「交换—缩堆—下滤」三件套，下滤传的堆大小是不断变小的 `end`，不是原始 n。
- 升序排序用大根堆（最大值换到末尾）；反过来求前 k 大要用**小**根堆，堆里始终只留 k 个元素。
- 建堆 O(n)、排序 O(n log n)、额外空间 O(1)、不稳定。

## 典型错误

### 错误 1：建堆循环从根往后遍历，堆性质根本没建立

- 现象：建堆后 `a[0]` 不是最大值，排序结果前几个位置错乱；换成随机数据有时又「看起来对」，因为部分子树碰巧已经是堆。
- 原因：写成了 `for (i = 0; i < n/2; i++) sink(a, i, n);`。下滤只保证「i 下沉到位」，前提是它的两个子树本来就是堆；从 0 往后走时孩子的子树还没被调整过，sink 会提前停下，根结点沉不下去。
- 引导问题：对下标 i 下滤时，你凭什么断定它的两个孩子所在的子树已经是合法堆？这个前提要求循环从哪一端开始、朝哪个方向走？

### 错误 2：选较大孩子时没判右孩子是否越界

- 现象：长度为偶数的数组在最后一个非叶结点处读到堆外的值；有时排序结果偶尔错，开 AddressSanitizer 才报越界读。
- 原因：写成 `if (a[child+1] > a[child]) child++;`，少了 `child + 1 < n` 这个条件。当 `2i+2 == n`（完全二叉树的最后一个结点只有左孩子）时，`a[child+1]` 已经是 `a[n]`，越界。
- 引导问题：完全二叉树上会不会有结点只有左孩子、没有右孩子？这时 `2*i+2` 等于多少，它还能作为下标用吗？

### 错误 3：排序阶段下滤传的堆大小还是 n

- 现象：排序结果尾部若干位置被打乱，刚放好的最大值又被搅回前面；n 越大错得越厉害，尾部的 log n 个元素基本乱序。
- 原因：`for (end = n-1; end >= 1; end--) { swap(a[0], a[end]); sink(a, 0, n); }` 里 sink 用的是 n，已经归位的 `a[end..n-1]` 仍被当成堆的一部分参与调整，最大值会被换回堆顶。
- 引导问题：第 end 个位置放好当前最大值之后，它还该不该参与下一轮下滤？sink 的第三个参数该怎么随 end 变化？

### 错误 4：把堆当成二叉排序树，用中序遍历验证

- 现象：学生画完堆后用「中序遍历是否升序」来自检，发现不升序就以为建堆失败，然后把代码改坏。
- 原因：堆只约束父子，不约束左右子树之间的大小，兄弟结点的顺序是任意的；有序性由「反复取堆顶」这个动作逐步产生，而不是结构本身自带。
- 引导问题：大根堆里左孩子 5、右孩子 9 合不合法？那么中序遍历出来会是升序吗？堆真正保证的是哪一件事？

## 分级练习

### 练习 1：手工建堆并模拟第一趟排序（难度：2）

- 题面：对 `[4, 9, 2, 7, 5, 1, 8]` 建大根堆（0 起下标），写出建堆完成后的数组；再做一次「交换堆顶与末尾 + 下滤」，写出结果。
- 一阶提示（反问）：最后一个非叶结点的下标是 `n/2 - 1`，n = 7 时它是几？建堆从它开始是往前还是往后走？
- 二阶提示（定位到行）：对下标 2 下滤时先看它的两个孩子 5、6；对下标 0 下滤时，两个孩子里较大的是 9，交换后还要接着对新的位置继续下滤，不能只换一次就停。
- 三阶提示（伪代码/类比）：像让每个小组长（父）比组员（孩子）高，从最小的组往上逐级换人，换下去的人到了新位置还要继续跟他的新组员比。
- 验收点：建堆后 `a[0]` 是 9，逐对检查每个父亲都不小于它的孩子；第一趟后最大值落在最后一个位置，前 n-1 个元素重新满足堆性质。

### 练习 2：补全下滤 sink（难度：3）

- 题面：补全 `sink(a, i, n)`，要求：父已经不小于较大的孩子时立刻返回、不做无谓交换；i 是叶子时立即返回且不访问越界下标；对任意「只有 i 处性质被破坏」的堆能整体恢复。
- 一阶提示（反问）：循环该不该继续，判断依据是「i 有没有孩子」，还是「i 是不是比孩子小」？前者要写成什么下标表达式？
- 二阶提示（定位到行）：`while` 条件是 `2*i+1 < n`（不是 `<=`）；取较大孩子时先默认 `child = 2*i+1`，只有 `child+1 < n` 且右孩子更大时才 `child++`；交换后一定要把 `i` 更新成 `child`，否则原地打转。
- 三阶提示（伪代码/类比）：石子沉水——每次跟两个儿子里更高的那个比，比儿子矮就换下去，直到两个儿子都不比它高，或者已经沉到水底（没有孩子）。
- 验收点：在合法堆上把 `a[0]` 改成 -1 后再调 sink，数组重新成为大根堆；对叶子调用 sink 立即返回且不越界读；`n = 1`、`n = 2` 正常；没有死循环。

### 练习 3：用小根堆求前 k 大（难度：4）

- 题面：从 n 个数里求最大的 k 个（k 远小于 n），要求空间 O(k)、时间 O(n log k)，并解释这里为什么必须用**小**根堆而不是大根堆。
- 一阶提示（反问）：堆顶是你最容易拿到、也最容易被淘汰的那个元素——如果要淘汰「当前 k 个里最小的」，堆顶应该是最小值还是最大值？
- 二阶提示（定位到行）：新元素只跟 `a[0]` 比较，只有它**大于**堆顶时才替换堆顶再 `sink(a, 0, k)`，否则直接丢弃；循环结束后堆里的 k 个元素就是答案（顺序不保证，需要时再排）。
- 三阶提示（伪代码/类比）：一间只有 k 个座位的贵宾室，门口保安只记得里面「最不重要的那位」；新来的人比他重要才挤掉他，否则原样放行。
- 验收点：结果集合与「全部排序后取前 k 个」一致；k = 1、k = n 两个边界正确；不额外开 O(n) 空间；总比较次数明显少于全排序。
