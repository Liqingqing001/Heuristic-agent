## 概念

用数组实现队列时，如果每次出队都把剩下的元素往前搬一格，出队就是 O(n)；如果不搬、只让 `front` 和 `rear` 往后走，数组前端会积累越来越多再也用不到的空位，`rear` 很快撞到数组末尾，明明还有空位却"队满"了——这叫**假溢出**。循环队列的解法是把数组首尾相接当成一个环，下标移动时对容量取模，`rear` 到末尾后回到 0，把前端腾出来的位置重新利用起来。

代价是出现一个新问题：`front == rear` 既可以解释为"队空"，也可以解释为"`rear` 转了一圈又追上了 `front`"，两种相反的状态共用一个条件。教材和工程里常用的三种破法：

1. **牺牲一个存储单元**：规定 `rear` 指向的位置始终空着，队满条件变成 `(rear + 1) % MAXSIZE == front`，队列最多存 `MAXSIZE - 1` 个元素；
2. **加一个计数器** `size`：入队 `++size`、出队 `--size`，空是 `size == 0`、满是 `size == MAXSIZE`，一格都不浪费；
3. **加一个标志位** `tag`：记录最后一次操作是入队还是出队，`front == rear` 时靠 `tag` 区分。

三种做法都正确，关键是**整个程序里只用一种**，并且把 `front`、`rear` 各自指向"队头元素"还是"下一个可写位置"写进注释——所有下标公式都建立在这一点上。

## 要点

- 循环队列用取模把数组卷成环：`rear = (rear + 1) % MAXSIZE`，`front = (front + 1) % MAXSIZE`。
- 牺牲一个单元的方案：队空 `front == rear`，队满 `(rear + 1) % MAXSIZE == front`，最大长度是 `MAXSIZE - 1`。
- 元素个数 `(rear - front + MAXSIZE) % MAXSIZE`，加 `MAXSIZE` 是为了不让 `rear - front` 出现负数。
- `front` 指向队头元素、`rear` 指向下一个可写位置时：入队是先写后移，出队是先取后移。
- 顺序队列的"满"是假溢出，循环队列的"满"才是真的没有空位——两者报错时含义完全不同。

## 典型错误

### 错误 1：把 rear == front 直接当成判满

- 现象：队列里明明还有空位，入队却返回"满"；或者队满时继续入队，把队头元素覆盖掉，出队顺序整体错乱。
- 原因：没有牺牲单元、也没有 `size` 或 `tag` 时，`front == rear` 在"一个元素都没有"和"一个空位都没有"两种情况下都成立，一个条件承担不了两种含义。
- 引导问题：你的队列"一个元素都没有"和"一个空位都没有"时，`front` 与 `rear` 的关系有什么不同？如果完全一样，你用什么信息把它们区分开？

### 错误 2：指针移动忘记取模

- 现象：下标跑到 `MAXSIZE` 之后越界写，或者程序不崩溃但 `rear` 越来越大，队列行为变得不可预测、时好时坏。
- 原因：`rear++` 只在"非循环"的数组队列里成立。循环队列里 `rear` 到 `MAXSIZE - 1` 之后必须回到 0，而不是变成 `MAXSIZE`。
- 引导问题：`rear` 从 `MAXSIZE - 1` 再加一时，你希望它指向数组的第几个位置？这个位置和 `MAXSIZE` 之间是什么运算关系？

### 错误 3：入队出队的"写/取"与"移指针"顺序写反

- 现象：入队后读出来的元素整体后移一位，`front` 位置上永远是垃圾值；或者最后一个元素怎么写都存不进去。
- 原因：`rear` 指向"下一个空位"时，必须先把值写进 `data[rear]`，再 `rear = (rear + 1) % MAXSIZE`；先移动指针等于越过了当前这个空位。出队同理，应先取 `data[front]` 再移动 `front`。
- 引导问题：`rear` 现在指的那一格，是"已经存了值的队尾"还是"还空着的位置"？先移动指针会把它跳过吗？

### 错误 4：求队长公式漏掉 + MAXSIZE

- 现象：队列长度偶尔变成负数或极大正数，遍历时循环次数爆炸，或者刚入队的元素查不到。
- 原因：`rear - front` 在 `rear` 已经绕回 0、而 `front` 还在数组后半段时是负数。C/C++ 里负数取模仍然是负数，必须 `+ MAXSIZE` 再取模。
- 引导问题：如果 `front = 8`、`rear = 2`、`MAXSIZE = 10`，你的公式算出来是几？这个数能当长度用吗？

## 分级练习

### 练习 1：补全入队与出队（难度：2）

- 题面：给定循环队列结构（数组 `data[MAXSIZE]`、`front`、`rear`，采用牺牲一个单元的方案），补全 `isEmpty`、`isFull`、`enQueue`、`deQueue`。
- 一阶提示（反问）：队满时 `rear` 和 `front` 是重合的还是相邻的？"空"和"满"各自对应哪一种位置关系？
- 二阶提示（定位到行）：`rear` 指向下一个空位，那么"写值"和"移动 rear"这两句谁在前？判满放在写入之前还是之后？
- 三阶提示（伪代码/类比）：像环形跑道上的两个人，队尾那个人前面永远留一个空位，一旦和队头相邻就说明满了。
- 验收点：`MAXSIZE = 3` 时最多存 2 个元素；入两个、出一个、再入两个不会覆盖旧数据；反复入满出空 1000 次无越界。

### 练习 2：用 size 计数改写，去掉牺牲的单元（难度：3）

- 题面：改造同一个循环队列，增加一个 `size` 记录当前元素个数，使 `MAXSIZE` 个空间全部可用，对外接口保持不变。
- 一阶提示（反问）：如果不肯丢那一个格子，你得额外记住什么信息才能分清空和满？
- 二阶提示（定位到行）：`size` 在入队、出队的哪一句旁边增减？判空判满还需要看 `front`、`rear` 的关系吗？
- 三阶提示（伪代码/类比）：像一个装了计数器的停车场，进出口不用特意留空位，看计数器就知道还剩几个车位。
- 验收点：`MAXSIZE = 3` 时能存满 3 个元素；满时入队失败且不覆盖队头；反复操作 1000 次后 `size` 仍等于实际长度。

### 练习 3：遍历循环队列并输出长度（难度：2）

- 题面：写一个函数，从队头到队尾打印循环队列的全部元素，打印完返回元素个数，要求函数不修改 `front` 与 `rear`。
- 一阶提示（反问）：如果直接用 `for (i = 0; i < MAXSIZE; i++)` 打印整个数组，会多打印出什么？
- 二阶提示（定位到行）：遍历起点是 `front` 还是 0？循环变量怎么移动才能绕回来？循环次数用长度公式控制，还是靠 `rear` 判断更稳？
- 三阶提示（伪代码/类比）：沿着环从队头出发走满"元素个数"步就停，走到空位上就说明已经出界了。
- 验收点：`front` 不为 0 时输出顺序仍正确；函数返回后 `front`、`rear` 未变；空队打印零个元素且不报错。
