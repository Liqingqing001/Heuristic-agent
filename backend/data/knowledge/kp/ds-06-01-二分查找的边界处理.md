## 概念

二分查找（折半查找）在有序顺序表上做：每次取中点比较一次，就能排除掉一半候选，代价 O(log n)。思想三行就能说完，真正难的是**三处边界必须自洽**：区间是闭区间 `[left, right]` 还是左闭右开 `[left, right)`；循环条件是 `left <= right` 还是 `left < right`；排除 mid 时写 `mid - 1`、`mid + 1` 还是只写 `mid`。

这三处一旦互相矛盾，只会出现两种症状：**漏检**——候选区间提前变成空，答案还在里面却从没被比较过；**死循环**——区间长度不再缩小，mid 反复落在同一位置。用循环不变量的说法最清楚：闭区间版本的「不变量」是「所有还没被排除的候选元素都在 `[left, right]` 里」；因此 `left > right` 才代表区间为空、可以判定失败，而 `left == right` 时区间里还有一个元素没比过，不能退出。既然每一轮都用 `a[mid]` 参与过比较，mid 本身就被排除了，更新时必须写 `left = mid + 1` 或 `right = mid - 1`，写成 `mid` 就等于什么都没排除。

还有一个隐藏的坑是整型溢出：`mid = (left + right) / 2` 在 left、right 都接近 `int` 上限时会先溢出成负数，再除以 2 得到非法下标，写成 `left + (right - left) / 2` 才安全。

```text
left = 0; right = n - 1                 // 闭区间 [left, right]
while left <= right:                    // 区间非空就继续
    mid = left + (right - left) / 2     // 向下取整，避免溢出
    if a[mid] == target: return mid
    if a[mid] < target:
        left = mid + 1                  // mid 已排除
    else:
        right = mid - 1                 // mid 已排除
return -1                               // 此时 left > right，区间为空
```

## 要点

- 先选定一种约定（推荐闭区间 `[left, right]` 配 `while (left <= right)`），三处写法当成一个整体记，不要东拼西凑。
- 排除 mid 必须带 ±1：`left = mid + 1`、`right = mid - 1`；只要有一处漏写，区间就可能不再缩小。
- 闭区间版循环结束时 `left > right`，并且 `left` 恰好等于「第一个大于 target 的下标」即插入位置，这是很多题目的副产品。
- 求第一个 ≥ target（lower_bound）时不能「命中即返回」，要改成 `right = mid - 1` 收缩并把 mid 记下来；求最后一个 ≤ target 时镜像处理。
- 用 `left < right` 配左闭右开 `[left, right)` 时，`right` 初值是 n、mid 向下取整、更新写 `right = mid` 而不是 `mid - 1`。
- 若真要用 `left = mid`，mid 必须取上整 `(left + right + 1) / 2`；取整方向与更新方式必须成对出现。

## 典型错误

### 错误 1：闭区间写法却用 left < right 作循环条件，漏检最后一个元素

- 现象：target 正好在区间最右侧时返回 -1；`n = 1` 时永远找不到；用 `[1,3,5,7,9]` 查 9 失败而查 1 成功。
- 原因：`while (left < right)` 在 `left == right` 时退出，此时 `[left, right]` 里还剩一个候选元素没比较过，而闭区间的不变量要求「`left > right` 才算空」。
- 引导问题：left == right 时区间里还有几个元素？这时候退出循环，那个元素被比较过了吗？

### 错误 2：右边界写成 right = mid，配合 while (left <= right) 死循环

- 现象：程序卡在某次循环里不返回，CPU 占满；用长度 2 的区间最容易复现（left = 0、right = 1）。
- 原因：`mid = (left + right) / 2` 向下取整，left = 0、right = 1 时 mid = 0；若 `a[0] > target` 走 `right = mid = 0`，区间从 [0,1] 变成 [0,0]，还有元素；下一轮 mid 仍是 0，`a[0] > target` 依旧成立，right 又被设成 0，永远出不去。
- 引导问题：mid 向下取整时，`right = mid` 真的把 mid 排除了吗？区间长度从 2 变成 1、再变成 0，靠的是哪一步？

### 错误 3：求左边界时「命中即返回」，返回的不是最左那个

- 现象：数组里有重复 target 时返回的下标随 mid 落点漂移，`[1,2,2,2,3]` 查 2 有时返回 1、有时返回 2；单测只测唯一元素的用例完全发现不了。
- 原因：`if (a[mid] == target) return mid;` 一命中就结束，但 mid 左边完全可能还有等于 target 的元素；求边界时命中不能返回，应记录当前答案后继续往左收缩（`right = mid - 1`）。
- 引导问题：mid 命中以后，你能确定 mid 左边没有和它相等的元素吗？如果不能，下一步该往哪半边收缩、答案变量该在哪一步更新？

### 错误 4：mid = (left + right) / 2 在极端数据上溢出成负数

- 现象：数组长度很小、元素值很普通时一切正常，把关键字换成接近 `INT_MAX` 的大数并在长数组上测试就崩溃或返回错误下标。
- 原因：`left + right` 超过 `int` 上限后先溢出成负数，再除以 2 得到负下标，`a[mid]` 直接越界。
- 引导问题：如果 left 和 right 都是 20 亿，它们的和是多少？这个和还装得进 `int` 吗？有没有只用减法的写法？

## 分级练习

### 练习 1：补全闭区间二分查找（难度：2）

- 题面：在升序数组里查找 target，返回下标或 -1；要求区间只剩一个元素时也必须比较，并分别给出 n = 0、n = 1、target 小于最小值、target 大于最大值四种输入的输出。

```text
left = 0; right = n - 1
while (______):
    mid = left + (right - left) / 2
    if a[mid] == target: return mid
    if a[mid] < target:  ______
    else:                ______
return -1
```

- 一阶提示（反问）：你这版代码在 `left == right` 时还会不会进循环？如果不会，那么「只剩一个元素」的那个候选是谁来比较的？
- 二阶提示（定位到行）：检查 `while` 的条件写的是 `<=` 还是 `<`；再检查两处更新是不是都带了 ±1，只有一处带、另一处不带也会出问题。
- 三阶提示（伪代码/类比）：像查纸质字典：每次翻到中间，看这页的词比目标大还是小，然后把「还要翻的那一叠」缩小一半；一页都不剩才算没找到。
- 验收点：四种边界输入结果都正确；不存在时返回 -1 而不是死循环；循环次数不超过 ⌈log₂(n+1)⌉；n = 0 时直接返回 -1 不访问数组。

### 练习 2：手写 lower_bound（难度：3）

- 题面：在升序数组里求第一个 ≥ target 的下标，不存在时返回 n；要求 O(log n)，且数组里有大量重复元素时返回最左边那个。

```text
left = 0; right = n            // 左闭右开 [left, right)
while (left < right):
    mid = left + (right - left) / 2
    if a[mid] < target:  ______
    else:                ______
return ______
```

- 一阶提示（反问）：既然命中不能马上返回，你打算靠什么保证循环一定结束、又靠什么保证最后停下的位置就是最左边界？
- 二阶提示（定位到行）：`a[mid] < target` 时左半（含 mid）都不可能是答案，应为 `left = mid + 1`；否则 mid 可能就是答案，应写 `right = mid`（不能写 `mid - 1`，那会把它排除掉）；循环结束时 `left == right`，直接返回 left。
- 三阶提示（伪代码/类比）：把数组看成一条「假、假、假、真、真、真」的序列，你要找的是第一个「真」——二分不是在找相等，而是在找性质翻转的那条缝。
- 验收点：target 比所有元素都小时返回 0、比所有元素都大时返回 n；重复元素返回最左下标；`n = 0` 返回 0；不会死循环。

### 练习 3：在旋转有序数组里查找（难度：4）

- 题面：数组由某个升序数组旋转而来（如 `[4,5,6,7,0,1,2]`），仍用 O(log n) 找到 target 的下标，找不到返回 -1。
- 一阶提示（反问）：mid 把数组切成两半，为什么其中至少有一半一定还是有序的？你怎么用 `a[left]`、`a[mid]`、`a[right]` 三者判断是哪一半？
- 二阶提示（定位到行）：先比较 `a[left] <= a[mid]` 判断左半是否有序；左半有序时用 `a[left] <= target && target < a[mid]` 决定往左收（`right = mid - 1`），否则往右（`left = mid + 1`）；右半有序时完全对称，注意四个比较都别漏等号。
- 三阶提示（伪代码/类比）：一本被从中间抽走一叠又接回去的字典，至少有一半还是连续按序排的；先确认哪半是顺的，再看目标在不在那半的数值区间里，在就翻那半、不在就翻另一侧。
- 验收点：各种旋转点（0、末尾、中间）都能找到；不存在的 target 返回 -1；重复元素不要求最左但必须是合法下标；循环次数仍是 O(log n)。
