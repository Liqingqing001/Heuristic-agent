## 概念

归并排序是分治三步最标准的例子：**分**——把区间从中间一刀切开；**治**——递归排好左右两半；**合**——把两个已经有序的段合并成一个有序段。它和快速排序刚好相反：快排的苦活在「分」（划分），合的时候什么也不用做；归并的「分」是免费的（算一个中点就切完），苦活全压在「合」上。

这个差别带来两个后果：归并排序的最坏时间复杂度也是 O(n log n)，不会像快排那样在坏输入上退化成 O(n^2)；而且在合并时先取左段的相等元素就能保证稳定。代价是需要一个和区间等长的辅助数组，空间 O(n)。

合并的细节全在边界上。中点 `mid = (left + right) / 2` 向下取整，左段是 `[left, mid]`、右段是 `[mid+1, right]`，两段都非空；用 i、j 两个游标各扫一段，谁小取谁。主循环的退出条件是两段**都**没取完，所以退出时必有一段先被取空、另一段还剩元素，这剩下的一段要原样搬到临时数组末尾——这一步漏掉就会少元素。最后把临时数组的结果写回原数组的 `[left, right]`，写回时目标下标要加上 `left`，而不是从 0 开始。

```text
merge_sort(a, left, right):
    if left >= right: return            // 0 个或 1 个元素天然有序
    mid = (left + right) / 2            // 向下取整，左段 [left, mid]
    merge_sort(a, left, mid)
    merge_sort(a, mid + 1, right)
    merge(a, left, mid, right)          // 合并两段有序区间
```

递归深度是 ⌈log₂n⌉ 层，每层合并的总代价是 O(n)，所以总时间 O(n log n)，与输入是否有序无关。

## 要点

- 递归基写 `left >= right`；写成 `left > right` 会让长度为 1 的区间也继续递归，只能靠 mid 碰巧收敛，深度不受控。
- 合并是「三段式」：主循环取较小的那个 → 搬左段剩余 → 搬右段剩余。第三段最容易漏，一漏就少元素。
- 比较用 `a[i] <= a[j]` 而不是 `a[i] < a[j]`：相等时先取左段，相等元素的前后顺序才不被交换，这就是稳定性。
- 写回写成 `a[left + k] = tmp[k]`；漏加 `left` 时只有 `left == 0` 的那一次是对的，右半区间全乱。
- 时间 O(n log n)（最好、最坏、平均都一样）、空间 O(n)、稳定；常用来求逆序对、做外部排序。
- 中点必须向下取整并配左段 `[left, mid]`；改成上取整 `(left + right + 1) / 2` 而区间不变，长度 2 时会无限递归。

## 典型错误

### 错误 1：合并时只写主循环，漏搬剩下那一段

- 现象：排序后元素个数没变，但有些位置是原数组的旧值、有些值重复出现；两段长度不等（比如 5 和 2）时特别明显，长度相等时偶尔看不出来。
- 原因：`while (i <= mid && j <= right)` 一退出就以为合并完了，没补 `while (i <= mid) tmp[k++] = a[i++];` 和 `while (j <= right) ...`。主循环退出时必有一段的元素还没进临时数组，写回时那些位置保留的是旧值。
- 引导问题：主循环退出的那一刻，是两段同时取完，还是只有一段取完？另一段剩下的元素现在在哪里，谁负责把它们搬过去？

### 错误 2：写回时下标漏加 left

- 现象：`left == 0` 的那次合并（最左半区）结果正确，右半区间整体错乱；小数组（n ≤ 4）常常对，n 一大就错。
- 原因：临时数组是从 0 开始填的，学生顺手写成 `a[k] = tmp[k]`，于是结果永远写回 `[0, 合并长度)`，而不是本层的 `[left, right]`，把左边已经排好的数据覆盖掉了。
- 引导问题：本层处理的区间是 `[left, right]`，临时数组下标 0 对应原数组的哪一个下标？写回时那个加号该加谁？

### 错误 3：中点取上整，左段区间没有缩小

- 现象：程序栈溢出或直接不返回；`n = 2` 的数组一进来就无限递归，`n = 1` 反而正常。
- 原因：写成 `mid = (left + right + 1) / 2` 却仍然递归 `[left, mid]`。当 `right == left + 1` 时 `mid == right`，左段又变成 `[left, right]`，与当前层的参数一模一样。
- 引导问题：`left = 0, right = 1` 时 `(left + right + 1) / 2` 等于几？这时左段 `[left, mid]` 比原区间短了吗？

### 错误 4：认为归并排序不需要额外空间

- 现象：学生把整个程序写成只有 `merge_sort` 一个函数、把临时数组声明成函数内的局部变量，处理 n = 100000 时栈/内存爆掉；或者把临时数组声明成全局的但仍按 `[0, n)` 写回。
- 原因：每层递归都开一个 `int tmp[len]` 会让总空间变成 O(n log n)，正确做法是只在最外层申请一个长度 n 的临时数组，逐层复用其中 `[left, right]` 那一段。
- 引导问题：这层递归的临时数组，能不能用上一层已经申请好的那一块？如果每层都自己开，n 层加起来一共开了多少空间？

## 分级练习

### 练习 1：手工合并两个有序段（难度：2）

- 题面：A = [12, 25, 38, 60]，B = [7, 25, 41]，写出按归并规则填写临时数组的完整过程；两个段里都有 25，指出先取哪一个、说明了什么性质。
- 一阶提示（反问）：每次决定「取谁」时，你比较的是哪两个元素？如果两个元素一样大，你的规则会偏向哪一边？
- 二阶提示（定位到行）：主循环条件是 `i <= 4 && j <= 3`（用 1 起编号时），当 B 先被取空，A 剩下的元素还需要再比较一次吗？
- 三阶提示（伪代码/类比）：像洗两叠已经排好的扑克牌，每次只看两叠最上面那张，小的先落下；一叠拿光了，另一叠剩下的直接整叠放上去。
- 验收点：临时数组长度为 7 且整体升序；两个 25 中 A 的在前（稳定）；能说出「A 先取空」还是「B 先取空」，以及谁需要整段搬运。

### 练习 2：补全 merge 的收尾与写回（难度：3）

- 题面：给出主循环 `while (i <= mid && j <= right)` 的比较与取元素部分，请补全省略的三段代码，使左右段长度不等（如 5 和 2）时结果仍正确，并保持稳定。

```text
// 主循环已写好：谁小取谁，i、j 各自后移
while (左段还有元素):   ______
while (右段还有元素):   ______
for (t = 0; t < 合并长度; t++):  ______
```

- 一阶提示（反问）：主循环退出后，两段里最多还有几段非空？这决定了你要写几个 `while`，以及每个 `while` 的条件是 `i <= mid` 还是 `i < mid`。
- 二阶提示（定位到行）：写回那行的目标下标写成 `a[____] = tmp[t]`；临时数组下标 t 从 0 起，原数组这一段从 `left` 起。
- 三阶提示（伪代码/类比）：搬家和贴门牌号——家具（元素）按顺序搬进临时仓库（tmp），搬完再按原楼层（left）的起始门牌号一个个贴回去，不能一律从 1 号门牌贴起。
- 验收点：长度为 7、8、9 的随机数组排序结果与库函数一致；左右段长度 5:2、1:1、2:5 三种情形都对；相等元素相对顺序不变；不出现旧值残留。

### 练习 3：在合并步骤里统计逆序对（难度：4）

- 题面：用归并排序的框架，在 O(n log n) 内统计数组中逆序对的个数（i < j 且 a[i] > a[j]），不允许 O(n^2) 暴力枚举。
- 一阶提示（反问）：合并两个有序段时，当你决定把右段的 `a[j]` 放进临时数组，说明左段还有多少个元素比它大？这个数量是不是一次就能算出来，而不用逐个比较？
- 二阶提示（定位到行）：只在「取右段元素」的那个分支里累加，累加量是左段尚未被取走的元素个数 `mid - i + 1`，而不是 j 的下标；取左段元素时不要累加。
- 三阶提示（伪代码/类比）：两个班按身高排好队合并，右班的某个人插进来时，左班站在他身后的人都得各记一次「逆序」，而这些人正好是左班还没被领走的那一截。
- 验收点：与暴力双重循环的计数完全一致；升序为 0、严格降序为 n(n-1)/2；全相等数组为 0；n = 0 或 1 不报错；只改合并那一段，递归结构不变。
