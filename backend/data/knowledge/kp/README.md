# 知识点库（kp）写作规范

本目录存放**结构化知识点**：每个知识点一个 Markdown 文件，文件头的 front matter（`---` 之间的部分）是机器可读的元数据，正文按固定小节组织。

后续 RAG 建库会读取这里的元数据，把 `kp_id`、章节、难度、前置知识一起写进向量库的 metadata，检索结果就能带上知识点编号——这是教师端统计「谁掌握了哪个知识点」的基础。

## 一、命名约定

```
ds-<章节两位>-<序号两位>-<中文短名>.md
例：ds-01-02-单链表插入与删除.md
```

- `ds` = data structure（固定前缀）
- 章节号与 `data/knowledge/lecture/` 下的编号一致：1 链表 / 2 栈与队列 / 3 二叉树与BST / 4 AVL树 / 5 排序 / 6 查找 / 7 图 / 8 线性表
- 文件名前缀必须等于 front matter 里的 `id`
- 以 `_` 开头的文件（如 `_TEMPLATE.md`）和 `README.md` 不参与校验

## 二、front matter 字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | `ds-01-02` 格式，全库唯一，必须与文件名前缀一致 |
| `chapter` | ✅ | int | 1-8，必须与 `id` 里的章节号一致 |
| `title` | ✅ | string | 知识点名称，≤ 60 字 |
| `difficulty` | ✅ | int | 1-5，1 入门、3 需要思考、5 综合 |
| `type` | ✅ | enum | `concept` 概念 / `operation` 操作 / `algorithm` 算法 / `application` 应用 |
| `tags` | ✅ | list | 2-5 个检索标签，行内写法 `[链表, 指针]` |
| `prereq` | ✅ | list | 前置知识点的 id，没有就写 `[]`；必须真实存在且不能成环 |
| `objectives` | ✅ | list | 学完能做到什么，1-3 条，每条 ≥ 6 字 |
| `source` | ✅ | string | 来源：`自编` / `OI Wiki` / 教材章节号等 |
| `version` | 可选 | int | 内容版本号，改结构时递增 |

## 三、正文小节

| 小节 | 必填 | 要求 |
|---|---|---|
| `## 概念` | ✅ | ≥ 120 字，讲清"是什么、为什么这样设计" |
| `## 要点` | 可选 | 结论性内容，适合被检索命中的短句 |
| `## 典型错误` | ✅ | ≥ 2 条，每条用 `### 错误 N：标题` 开头，含「现象 / 原因 / 引导问题」 |
| `## 分级练习` | ✅ | ≥ 2 道，每道含「题面 / 一阶提示 / 二阶提示 / 三阶提示 / 验收点」 |

分级练习的三阶提示对应项目的「三阶提示法」：**一阶反问 → 二阶定位到行 → 三阶伪代码/类比**。这是「不泄题」的落点，也是后面结构化 JSON 里 `hint_level_reached` 的依据。

## 四、不泄题红线（校验脚本会检查）

- 禁止 `int main(`、`#include` 等可直接编译的完整程序
- 单个代码块建议 ≤ 15 行
- 不要出现"完整代码如下""标准答案如下"这类表述
- 允许：伪代码、≤ 5 行的关键片段、ASCII 图、类比

## 五、怎么写一条

1. 先写 `## 概念`，用一段话把「它解决什么问题」说清楚；
2. 写 `## 要点`，把可以当结论背的 2-4 句提炼出来（检索命中的往往是这些句子）；
3. 回忆你批改作业时见过的错法，写进 `## 典型错误`，`引导问题` 要写成**真能问出口的一句话**，不是"去看书"；
4. 每道练习先写三阶提示，最后才写验收点——顺序反了容易写成答案。

## 六、校验

在 `backend/` 目录下运行：

```powershell
py scripts\check_kp.py            # 校验 + 覆盖矩阵
py scripts\check_kp.py --strict   # 警告也算失败，提交前跑
py scripts\check_kp.py --json     # 机器可读，给 CI 用
```

退出码：`0` 通过、`1` 有错误、`2` 脚本本身出错。
