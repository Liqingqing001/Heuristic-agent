## 概念

单源最短路径问题问的是：给定源点 s，求 s 到其余每个顶点的最短路径长度。Dijkstra 的思路是把顶点分成两堆——已经确定最短距离的（visited 为真）和还没确定的（未访问集合）。每一轮从未访问集合里挑出 dist 值最小的那个顶点 u，宣布 dist[u] 就是 s 到 u 的最终答案，然后拿 u 去松弛它的所有出边：如果 dist[u] + w(u,v) 比 dist[v] 还小，就把 dist[v] 改小。整个过程需要一个 dist 数组存「当前已知的最短估计」、一个 visited 数组标记「答案已定稿」，想还原路径时再加一个 prev 数组记录前驱。

为什么选中 u 就能宣布它定稿？因为所有边权都非负，任何一条「先绕去别处再回到 u」的路径，长度只会比 dist[u] 更大，不可能反过来给出更短的解。这条推理正是贪心成立的根基，也意味着「边权非负」不是可有可无的附加条件：一旦出现负权边，绕远路反而可能更短，已经宣布的答案会被推翻，Dijkstra 的输出就不再可靠，这时应该换 Bellman-Ford 或 SPFA。

朴素实现（邻接矩阵）每轮扫一遍 dist 找最小值是 O(n)，共 n 轮，总复杂度 O(n²)；用邻接表加优先队列（堆）可以做到 O((n+e)log n)。要注意的是，Dijkstra 求的是「单源」：换一个源点就得整体重跑，多源最短路要用 Floyd。

## 要点

- 三个数组：dist 存当前最短估计、visited 标记是否定稿、prev 存前驱用于还原路径。
- 初始化只做两件事：dist[s] = 0（其余为 INF）、visited 全为假。
- 每轮固定三步：在未访问集合里取 dist 最小的 u → 标记 visited[u] = 真 → 对 u 的每条出边松弛。
- 松弛的判据是 `dist[u] + w < dist[v]` 才更新，直接赋值等于把更长的路径写进答案。
- 边权非负是正确性前提；有负权边时改用 Bellman-Ford / SPFA。
- 复杂度：邻接矩阵朴素版 O(n²)，邻接表 + 优先队列 O((n+e)log n)。

## 典型错误

### 错误 1：松弛时直接赋值，不比较原来的 dist

- 现象：样例能过，自己造的图就错，某些顶点的 dist 比正确答案还大；把边的输入顺序换一下，结果又变了。
- 原因：写成 `dist[v] = dist[u] + w;`，少了 `if (dist[u] + w < dist[v])` 这层判断，于是后发现的、更长的那条路径把先前记录的更短估计覆盖掉了，dist 只能变大不能变小。
- 引导问题：v 现在记录的是一条长度为 5 的路，你新算出的是 9，你要不要把 9 写进去？你写之前有没有和原来那个 5 比过？

### 错误 2：选最小值时没有排除已定稿的顶点

- 现象：程序进入死循环，每一轮都选中同一个顶点；或者某个顶点的 dist 先被改小、过几轮又被改大，最终答案忽大忽小。
- 原因：每轮在全部 n 个顶点里找 dist 最小，却没有跳过 `visited[u]` 为真的顶点。已定稿的顶点 dist 不会再变，反复选中它只是空转，未访问集合的规模永远不会缩小。
- 引导问题：第二轮找最小值的时候，上一轮那个 dist 最小的顶点还在候选里吗？它已经在 visited 里了，凭什么还要参与这一轮的比较？

### 错误 3：把「无穷大」取成 0 或者一个很小的数

- 现象：源点根本到不了的顶点在结果里显示 0 或某个正常数字，「不可达输出 -1」的分支永远不触发；换成 `0x7fffffff` 之后，`dist[u] + w` 直接变成负数，那些顶点又被当成「超级近」。
- 原因：INF 取 0，等于一开始就宣布所有顶点「距离为 0」，初始状态就是错的；取 `INT_MAX` 又不防加法溢出，加一条边权就回绕成负数。
- 引导问题：一个顶点从源点压根走不到时，它的 dist 应该长什么样？这个值再加上一条边权之后，还能保证「比任何真实路径都大」吗？

### 错误 4：图里有负权边，还硬套 Dijkstra

- 现象：图里有一条 -2 的边，正确答案是 0，程序输出 1；或者结果里出现「某个顶点距离为负」这种看着就不对的值，检查半天发现代码逻辑和课本一模一样。
- 原因：Dijkstra 宣布答案的依据是「绕远路只会更长」，负权边恰恰破坏了这个前提——先经一个大正权顶点定稿，再走一条负边回来反而更短，但那个顶点已经 visited，不会再被松弛。这是算法前提不满足，不是代码写错。
- 引导问题：宣布 u 定稿时，你用的理由是「任何绕路都更远」；如果某条边的权值是负的，这句话还成立吗？这时该换哪个算法？

## 分级练习

### 练习 1：手工模拟 Dijkstra 并求出到 5 号顶点的最短路（难度：3）

- 题面：有向带权图如下（顶点 1..5，括号内是边权），源点为 1。请逐轮模拟 Dijkstra，画出每轮结束后的 dist 数组，最后给出 dist[5] 以及对应的路径。

  ```text
  1: →(2,10)  →(3,3)
  2: →(4,2)
  3: →(2,4)   →(4,8)
  4: →(5,7)
  5: （无出边）
  ```

- 一阶提示（反问）：第 2 轮你要从没定稿的顶点里挑 dist 最小的，这时 2 号和 3 号的 dist 分别是多少？先挑谁，会影响到 2 号最终的值吗？
- 二阶提示（定位到行）：检查你处理 3 号顶点时写的那句松弛——`dist[2]` 原来是 10，现在算出 3+4=7，你有没有执行更新？如果漏了这次更新，后面 dist[4]、dist[5] 会一路错下去。
- 三阶提示（伪代码/类比）：每轮就三件事——挑出未访问里 dist 最小的、标记它、用它去改邻居的估计；像往一圈城市里逐个「盖章确认」，盖章的城市不再改。
- 验收点：dist = [0, 7, 3, 9, 16]（按 1..5 顺序）；dist[5] = 16，路径 1→3→2→4→5；能指出 2 号顶点的 dist 被从 10 改小到 7 的那一步。

### 练习 2：找出这段松弛代码的问题（难度：3）

- 题面：下面是从某同学的 Dijkstra 里截出来的片段，其余部分（初始化、选最小顶点）都正确。请指出这一段的错误，说明它会让哪些顶点的答案变大，并给出修改方向。

  ```text
  for (v = 1; v <= n; v++)
      if (w[u][v] < INF)
          dist[v] = dist[u] + w[u][v];
  ```

- 一阶提示（反问）：这段循环有没有「保留原来更小的那个」的意思？如果 dist[v] 早就是一个很小的数，这行执行完会发生什么？
- 二阶提示（定位到行）：看 `dist[v] = ...` 这一行，等号右边是新的候选距离，等号左边的旧值被读到过吗？松弛到底应该取两者中的哪一个？
- 三阶提示（伪代码/类比）：松弛像记录「目前找到的最短路线」——新路线只有比本子上记的更短，才值得划掉重写。
- 验收点：能指出缺少比较、只保留新值；能说明旧值更小时会被无谓覆盖；改法是加 `if (dist[u] + w < dist[v])` 再赋值，或对两边取较小值。

### 练习 3：负权边为什么让 Dijkstra 出错（难度：4）

- 题面：有向图有三个顶点，边 1→2 权 1、1→3 权 2、3→2 权 -2，源点为 1。请按 Dijkstra 的规则模拟一遍，写出程序会输出的 dist[2]，再算出真实的最短距离，并指出是哪一步「宣布」造成了偏差；最后说明该换用什么算法。

  ```text
  1 → 2 :  1
  1 → 3 :  2
  3 → 2 : -2
  ```

- 一阶提示（反问）：第一轮你会先挑中 2 号还是 3 号？为什么？挑了它之后，它还会不会再次进入候选集合？
- 二阶提示（定位到行）：处理 3 号顶点时算出 dist[2] = 2 + (-2) = 0，这个 0 比现在的 dist[2]=1 小，但你的代码里还有机会写进 dist[2] 吗？卡在哪一行？
- 三阶提示（伪代码/类比）：这叫「定稿定早了」。像先按距离远近给选手排序颁奖，结果后来发现有人抄近道，可奖已经发出去、名单不再修改。
- 验收点：能说出 Dijkstra 先把 2 号定稿为 1、之后因 visited 不再更新；真实答案是 0（路径 1→3→2）；能说明负权破坏了「绕路只会更远」的前提，应改用 Bellman-Ford 或 SPFA。
