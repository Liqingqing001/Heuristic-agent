## 概念

快速排序的核心不是「排序」，而是**划分**（partition）：在一趟扫描里选一个基准值 pivot，把区间重新摆成「左边都不大于 pivot、右边都不小于 pivot」的两段，pivot 自己被摆到两段的交界处。这一趟结束，pivot 的最终下标就确定了——它左边全不比它大、右边全不比它小，之后无论怎么递归都不会再动它。剩下的活儿只是对左右两段各自重复同样的划分，这就是分治：快排的「分」最费劲，「合」是免费的，既不用像归并那样另开数组，也不用把临时结果写回；代价全部押在划分是否平衡上。

如果每一趟都把区间切成 1 : n-1（例如基准固定取首元素，而数组已经基本有序），递归深度就退化成 n，时间复杂度从 O(n log n) 掉到 O(n^2)。所以「基准怎么选」「i 和 j 怎么走」「基准最后跟谁交换」这三件事，才是快排真正要背下来的部分。一通划分通常写成这样（基准取 `a[low]`，区间 `[low, high]`）：

```c
pivot = a[low];
i = low; j = high;
while (i < j) {
    while (i < j && a[j] >= pivot) j--;   // 右指针先走，跳过 >= pivot 的
    while (i < j && a[i] <= pivot) i++;   // 再走左指针，跳过 <= pivot 的
    if (i < j) swap(a[i], a[j]);
}
swap(a[low], a[i]);   // 此时 i == j，这个位置就是基准的最终下标
```

注意最后一行交换的是 `a[i]`，不是随便哪个位置：循环停下时 `i == j` 且 `a[i]` 一定不大于 pivot，把基准换到这里才保证「左边全小、右边全大」。

## 要点

- 一趟划分结束时 `i == j`，且 `a[i] <= pivot`；基准必须与这个位置交换，落到它身上的下标就是它在有序数组里的最终位置。
- 两个内层 `while` 的循环条件里都必须有 `i < j` 保护，缺了它就会有一侧指针走出 `[low, high]` 造成越界读。
- 右指针必须先动：这样停下时 `a[i]` 才一定不大于 pivot；先动左指针在 `[49, 38, 65, ...]` 这类数据上会把比基准大的元素换到表头。
- 递归区间是 `[low, p-1]` 和 `[p+1, high]`，不含 `p` 本身；写成 `[low, p]`／`[p, high]` 会无限递归。
- 平均时间 O(n log n)、最坏 O(n^2)、平均额外空间 O(log n)（递归栈），不稳定排序。
- 另一种常见写法是 Lomuto 划分：i 记录「≤ pivot 区」的右边界，j 从左往右扫，谁不大于 pivot 就 `i++` 再交换——循环变量只有一个，但交换次数更多。

## 典型错误

### 错误 1：内层循环漏掉 i < j 保护，指针越出区间

- 现象：对一段全部元素都不小于 pivot 的数据（例如已升序数组取首元素作基准）程序崩溃或读出乱数；AddressSanitizer 报 heap-buffer-overflow。学生常误以为是「数组太大」。
- 原因：写成 `while (a[j] >= pivot) j--;`，只比较了元素值，没同时检查 `i < j`，j 会从 high 一路减到 low-1，下一轮 `a[j]` 已经落在 `[low, high]` 之外。
- 引导问题：如果 [low, high] 里一个比 pivot 小的元素都没有，j 会在哪里停下来？这个下标还在区间里吗？

### 错误 2：等号写成严格不等，遇到与基准相等的元素时 i、j 都不前进

- 现象：排序卡住、程序转圈不返回；数组里一旦出现两个以上和 pivot 相等的元素就复现，而互不相同的随机数据反而一切正常。
- 原因：内层写成 `while (i < j && a[j] > pivot) j--;` 和 `while (i < j && a[i] < pivot) i++;`，遇到 `a[j] == pivot` 和 `a[i] == pivot` 时两个指针都立刻停下，交换两个相等的元素等于没换，下一轮又停在同一对下标上，形成死循环。
- 引导问题：当 a[i] 和 a[j] 都等于 pivot 时，这一轮交换之后数组有任何一个位置变了吗？那下一轮这两个指针会不会停在原来的位置？

### 错误 3：递归区间把基准包含进去，栈溢出

- 现象：小数据能出结果，数据一多就崩；调试器里看到同一组 `(low, high)` 参数反复入栈，最后栈溢出。
- 原因：写成 `quick_sort(a, low, p)` 和 `quick_sort(a, p, high)`，当 `p == low`（基准本来就在最左端）时左区间长度一点没变、参数与上一层完全相同，于是无限递归。
- 引导问题：p 位置上的元素已经是最终位置了，递归左段时 `high` 该传 `p` 还是 `p - 1`？传错的结果是区间不变还是区间为空？

### 错误 4：基准归位时交换错对象，左边的元素比基准还大

- 现象：排序结果整体错位，某个位置的元素比它左边的元素小；继续递归后某段区间反复被划分却始终不收敛。
- 原因：Hoare 版循环停下来时 `i == j` 且 `a[i] <= pivot`，若写成 `swap(a[low], a[j])` 而 j 在另一套变体里停在「≥ pivot 区」的第一个位置，就会把一个不小于 pivot 的元素换到表头。
- 引导问题：循环结束后 a[i] 和 pivot 谁大？你交换的那个位置，能保证它左边的元素全都不大于 pivot 吗？

## 分级练习

### 练习 1：手工模拟一趟划分（难度：2）

- 题面：数组 `[49, 38, 65, 97, 76, 13, 27, 49]`，以第一个元素为基准，按课上 i/j 双指针规则写出每一次交换后的数组，并给出基准最终落到的下标。
- 一阶提示（反问）：j 先动还是 i 先动？j 停下时它指向的元素一定小于基准吗？
- 二阶提示（定位到行）：每一步先看 `a[j] >= pivot` 让 j 减了几次，j 停住以后再看 `a[i] <= pivot`；只有 `i < j` 时才交换，交换完两个指针都还要继续往里走。
- 三阶提示（伪代码/类比）：像两个人从队伍两头往中间挤，各自把「不该留在这一侧的人」指出来，凑成一对就换位置，两人撞上就停。
- 验收点：基准左侧元素都不大于它、右侧元素都不小于它；基准下标与你记下的交换过程一致；整个数组没有被漏掉的元素。

### 练习 2：给划分循环补上越界保护（难度：3）

- 题面：下面这段划分只写了最内层的 while，请补全成能在「整段都不小于基准」「整段都相等」「空区间」三种输入下都不越界、不死循环的版本。

```text
i = low; j = high;
while (i < j):
    while (______): j--
    while (______): i++
    if (i < j): swap(a[i], a[j])
swap(a[low], a[i])
```

- 一阶提示（反问）：指针往里走的每一步，都得先问一句「它还能再走吗」——这个「还能」由哪两个条件共同决定？少一个会出什么事？
- 二阶提示（定位到行）：两个内层 `while` 的条件里，除了 `a[j] >= pivot` 之外还缺一个必须放在前面的比较；缺了它，j 会从 high 一路减到 low-1，下一轮就访问到区间外。
- 三阶提示（伪代码/类比）：两个人在走廊两头对着走，谁都不许走过对方站的位置——「不许越过对方」就是那条 `i < j`，它跟元素比较是并列的、不是可选项。
- 验收点：三种极端输入都返回一个落在 `[low, high]` 内的下标；循环退出时 `i == j` 且 `a[i] <= pivot`；全相等的数组不会卡住。

### 练习 3：用划分求第 k 小元素（难度：4）

- 题面：不把数组完整排好，只利用划分找出无序数组中第 k 小（k 从 1 开始）的元素，要求平均 O(n)。
- 一阶提示（反问）：一趟划分之后，基准的下标 p 告诉你「它前面有几个元素」——这个信息能不能直接让你扔掉一整段？
- 二阶提示（定位到行）：拿目标下标 `k-1` 与 p 比较：相等就返回 `a[p]`；小于 p 只递归左段；大于 p 只递归右段，并把目标下标换算成右段内的相对位置。
- 三阶提示（伪代码/类比）：像查纸质字典找第 k 个字，翻到中间发现前面已经有 p 个字，比 k 大就只查前半本、比 k 小就只查后半本，另外半本连看都不用看。
- 验收点：只递归一侧（不是两侧都递归）；k 取 1、n、中间值时结果与「排序后取下标 k-1」一致；不额外开 O(n) 空间。
