# 悬空指针（Dangling Pointer）

## 现象

程序访问一块已经被释放（free/delete）的内存，出现随机崩溃、读到垃圾值，或偶尔正常（未定义行为）。

## 原因

指针仍保存着已释放内存的地址，而该内存已被归还给堆管理器，可能被重新分配。此时通过该指针读写就是访问悬空指针。典型场景：释放后未置空、函数返回局部变量的地址、delete 后另一个指针仍指向同一块内存。

## 如何定位

1. 找出所有 `free(p)` / `delete p` 的位置，检查其后是否还有对 `p` 的读写。
2. 检查多个指针是否指向同一块内存（别名），其中一个释放后另一个仍在用。
3. 检查函数是否返回了栈上局部变量/数组的地址。
4. 用 AddressSanitizer（`-fsanitize=address`）或 valgrind 检测 use-after-free。

## 预防

释放后立即置空：`free(p); p = NULL;`；让内存的所有权单一清晰；避免返回局部变量地址。
